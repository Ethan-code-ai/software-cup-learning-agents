# 第 2 章 线性表与链表

## 核心概念

顺序表使用连续存储空间，支持 O(1) 随机访问，但在中间插入或删除时需要移动元素。动态数组扩容通常采用倍增策略，使尾部追加的摊还复杂度接近 O(1)。

链表由结点和指针组成。单链表插入、删除已知位置附近的结点只需修改指针，但随机访问需要 O(n)。双链表保存前驱和后继指针，删除已定位结点更方便。

## 例题与练习

例题：频繁按下标读取应优先选择顺序表，频繁在头部插入可选择链表。练习：实现反转单链表、合并两个有序链表，并比较两种线性表的复杂度。

## 易错点

删除链表结点前要保存后继指针；顺序表扩容后旧数组地址可能失效；“插入快”必须说明是否已经拿到目标位置。

## Python 代码案例

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

def reverse(head):
    previous = None
    current = head
    while current is not None:
        following = current.next
        current.next = previous
        previous, current = current, following
    return previous
```

## 知识点拆解

### 1. 顺序表操作

顺序表的访问按地址计算，复杂度为 O(1)。尾部追加在容量充足时为 O(1)，扩容时需要复制 O(n) 个元素；如果容量按倍数增长，连续追加的摊还复杂度为 O(1)。中间插入和删除需要移动后续元素，平均为 O(n)。

### 2. 链表操作

单链表结点包含数据域和后继指针。已知前驱结点时插入和删除为 O(1)，但寻找前驱需要 O(n)。双链表增加 prev 指针，牺牲空间换取更方便的双向移动。带头结点的链表可以统一空表和头部插入的边界逻辑。

### 3. 结构选择

| 场景 | 推荐结构 | 原因 |
|---|---|---|
| 高频随机访问 | 顺序表 | 下标访问 O(1) |
| 高频头部插入 | 链表或双端队列 | 不需要移动全部元素 |
| 频繁中间插入且已定位 | 链表 | 修改指针即可 |
| 需要缓存局部连续数据 | 顺序表 | 局部性和空间效率更好 |

## 例题详解

例题一：删除单链表中第 k 个结点。先用指针找到第 k-1 个结点，再保存待删除结点的 next，把前驱的 next 指向后继。找位置的成本是 O(n)，删除动作本身是 O(1)。

例题二：判断单链表是否有环。使用快慢指针，慢指针每次走一步，快指针每次走两步。如果存在环，两者最终会在环内相遇；如果快指针到达 None，则无环。时间复杂度 O(n)，额外空间 O(1)。

## 练习题

1. 实现单链表的头插、尾插、按值删除和反转。
2. 合并两个递增单链表，要求不创建新的数据结点。
3. 设计一个支持 O(1) 均摊尾部追加的动态顺序表。

## 参考答案

1. 头插只需更新新结点的 next 和 head；删除时处理空表、删除头结点和不存在目标三种情况。
2. 使用 tail 指针逐次连接较小结点，最后接上非空剩余链表。
3. 容量不足时申请两倍数组并复制旧元素，size 表示有效元素数量，capacity 表示数组容量。

## 易错点复盘

链表删除不能在丢失 next 后再访问后继；循环遍历要保证指针最终向 None 移动；顺序表的 size 和 capacity 不是同一个概念；复杂度必须说明“是否已经拿到结点位置”。

## 实验任务

分别实现顺序表和单链表，在 n=10、100、1000、10000 时测量随机访问、头部插入和尾部追加。记录操作耗时并解释测量结果与理论复杂度的差异。

## 课堂小结

顺序表强调连续空间、缓存局部性和随机访问；链表强调结点重连和局部修改。写复杂度时要说明“位置是否已知”，因为找到位置和执行修改是两个不同阶段。工程代码还要处理空表、单结点、删除头尾和重复值。
