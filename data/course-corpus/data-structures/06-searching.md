# 第 6 章 查找

## 核心概念

顺序查找不要求数据有序，最坏复杂度为 O(n)。二分查找要求序列有序，每次排除一半候选范围，复杂度为 O(log n)。边界条件是二分查找最容易出错的地方。

哈希表通过哈希函数把键映射到桶中，平均查找接近 O(1)，冲突可以用链地址法或开放定址法处理。二叉搜索树要求左子树键小于根、右子树键大于根，退化时复杂度可能降为 O(n)。

## 例题与练习

练习：分别实现左边界二分查找、哈希表计数和二叉搜索树插入；说明有序条件、冲突和退化对复杂度的影响。

## 易错点

二分查找循环区间必须统一使用闭区间或半开区间；哈希表平均 O(1) 不是最坏 O(1)；普通二叉搜索树不自动保持平衡。

## Python 代码案例

```python
def lower_bound(values, target):
    left, right = 0, len(values)
    while left < right:
        middle = (left + right) // 2
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle
    return left
```

## 知识点拆解

### 1. 顺序查找与二分查找

顺序查找适合无序数据，最坏比较 n 次。二分查找维护一个候选区间，每次比较中点并排除一半。闭区间写法使用 `left <= right`，半开区间写法使用 `left < right`；两种写法不能混用边界更新。

### 2. 哈希表

哈希表把 key 映射到桶。好的哈希函数应尽量均匀分布，装载因子过高时需要扩容。链地址法在桶中保存多个元素，开放定址法在数组中寻找下一个空槽。平均查找接近 O(1)，最坏情况仍可能为 O(n)。

### 3. 二叉搜索树

二叉搜索树的中序遍历有序。查找、插入和删除的复杂度与树高 h 相关，为 O(h)。随机插入通常较平衡，但按递增顺序插入会退化成链表；AVL 或红黑树通过旋转维持 O(log n) 高度。

## 例题详解

例题一：找第一个大于等于 target 的位置。若 `values[mid] < target`，答案一定在右侧；否则保留 mid 并收缩右边界。循环结束时 left 就是 lower_bound，若 left 等于长度则不存在满足条件的元素。

例题二：统计数组中每个单词的频率。使用哈希表把单词映射到计数，每个单词平均 O(1) 更新，总时间 O(n)，空间 O(k)，其中 k 是不同单词数。

例题三：删除二叉搜索树结点。叶子直接删除；只有一个孩子时让父结点连接孩子；有两个孩子时用右子树最小结点或左子树最大结点替换，再删除替换结点。

## 练习题

1. 实现精确查找、lower_bound 和 upper_bound。
2. 设计支持重复 key 的哈希表计数接口。
3. 实现二叉搜索树的查找、插入和删除，并输出中序序列。

## 参考答案

1. lower_bound 保留满足条件的 mid，upper_bound 把条件改为 `values[mid] <= target`。
2. 使用 `dict.get(key, 0) + 1`，查询时返回 0 作为不存在 key 的默认值。
3. 删除两个孩子的结点时选择后继，复制后继值，再在右子树中递归删除后继。

## 易错点复盘

二分查找必须先确认有序；整数中点应避免溢出；哈希表的平均复杂度不是严格保证；普通 BST 的复杂度由高度而不是结点总数直接决定。

## 实验任务

比较顺序查找、二分查找和哈希查找在相同数据规模下的比较次数。额外构造有序递增插入的 BST，观察其高度和查找性能如何退化。

## 课堂小结

查找算法的前提比代码本身更重要：二分查找依赖有序性，哈希查找依赖合理的哈希函数和装载因子，二叉搜索树依赖高度。面对新问题，应先判断数据是否静态、是否有序、是否允许额外空间以及是否需要支持动态插入。
